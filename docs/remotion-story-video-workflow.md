# Remotion物語動画ワークフロー

このドキュメントは、新しい台本からRemotionの長尺動画を作るときに、初心者でも迷いにくいようにするための進行手順です。

ポイントは、いきなりRemotionやmanifestを作らないことです。先に厳密テロップ分割、シーン計画、画像グループ、画像プロンプトを人間が確認できるようにしておくと、あとから直す作業がかなり楽になります。

## 最初にCodexへ言うこと

```text
新しい台本を渡します。
まず厳密テロップ分割から確認しながら進めてください。
開始番号や章の範囲で不明な点があれば、先に質問してください。
```

補助資料も一緒に渡す場合は、次のように言うと安全です。

```text
完成台本と補助資料を渡します。
動画本編に使ってよいのは【A. 完成台本】だけです。
【B. 補助資料】は、説明欄作成、チャプター調整、参考文献整理、タグ候補作成のためだけに使ってください。
台本と補助資料の境界が不明な場合は、作業前に質問してください。
```

## 全体の流れ

1. 台本と、必要なら補助資料を渡す
2. 本編に使う範囲と、補助資料として扱う範囲を確認する
3. 厳密テロップ分割を作る
4. 人間がテロップ分割を確認・修正する
5. シーン計画を作る
6. 人間がシーン計画を確認・修正する
7. 画像グループを作る
8. 人間が画像グループを確認・修正する
9. 画像プロンプトを作る
10. 外部の画像生成AIで画像を作る
11. 画像と音声をプロジェクトへ入れる
12. manifestを作る
13. Remotionで確認する
14. 読み間違い修正・画像差し替えを行う
15. 手作り演出の候補を出す
16. 必要な場面だけ動画生成AI用プロンプトを作る
17. 完成版MP4を書き出す
18. 補助資料と実際の動画内容をもとに、YouTube説明欄の最終版を作る

## 0. 台本と補助資料の切り分け

補助資料は、動画本編の素材ではありません。

使ってよい用途:

- 動画の中心論点を理解する
- 説明欄の最終版を作る
- チャプターを実際の動画時間に合わせる
- 参考文献や出典を整理する
- YouTubeタグ候補を出す
- 作業中の変更点を記録する

使ってはいけない用途:

- ナレーション本文に混ぜる
- テロップ本文にする
- 勝手に新しい本編シーンとして追加する
- 未確認のURLや出典を作る

台本と補助資料の区切りが曖昧な場合、Codexは先に質問します。

## 1. 厳密テロップ分割

台本を受け取ったら、Codexはまず厳密テロップ分割案を作ります。

この段階では、画像グループや演出案は付けません。原文を一字一句そのまま使い、テロップとして読みやすい単位に分けるだけです。

確認すること:

- 開始番号が合っているか
- 原文にない言葉が入っていないか
- 原文の言葉が消えていないか
- 1行20文字以内になっているか
- 1シーン最大2行になっているか
- 全シーンをつなげたときに原文と一致するか

開始番号、章の範囲、変換する本文が不明な場合は、Codexが先に質問します。

## 2. シーン計画

厳密テロップ分割が承認されたら、次にシーン計画を作ります。

確認すること:

- 区切りが細かすぎないか
- 1シーンが長すぎないか
- 感情の変化や説明の区切りが自然か
- 後で画像を作りやすい単位になっているか

この段階では、まだmanifestを作らないのが大切です。

## 3. 画像グループ

画像グループとは、複数のシーンで同じ画像を使うためのまとまりです。

例:

- 同じ場所で会話が続く場面
- 同じ食卓を見せながら説明する場面
- 同じ診察室で会話する場面

確認すること:

- 同じ画像で違和感がないか
- ここだけは別画像にした方がよい場面はないか
- 画像枚数が多すぎないか
- 逆に、使い回しすぎて単調にならないか

## 4. 画像プロンプト

画像グループが決まったら、外部の画像生成AIに貼り付けるためのプロンプトを作ります。

Codexにはこう頼むと分かりやすいです。

```text
画像プロンプトをコピーできる形で出してください。
画像内に文字は入れないでください。
```

画像は、ユーザーが使いたい画像生成AIで作ります。作った画像をプロジェクト内の画像フォルダへ入れたあと、Codexにファイル名を伝えます。

## 5. manifest

manifestは、動画の設計図です。

manifestに入るもの:

- シーンID
- 本文
- 字幕
- 画像ファイル
- 音声ファイル
- 表示時間
- 必要に応じて動画ファイル

厳密テロップ分割、シーン計画、画像グループを確認してからmanifestを作ると、後の修正が楽になります。

## 6. Remotion確認と修正サイト

Remotionで動画を確認したあと、読み間違いや画像差し替えをしたい場合は、修正サイトを使います。

このテンプレートでは、以下で起動します。

```bash
npm run tools
```

ブラウザで開くURL:

```text
http://localhost:3101/
```

ここでできること:

- 読み間違い修正
- 1シーンだけ音声を作り直す
- 画像差し替え
- 動画ファイルへの差し替え

## 7. 手作り演出

Remotionで基本形ができたら、量産型に見えにくくするために、手作り演出の候補を出します。

Codexにはこう言えます。

```text
新しい物語のmanifestから、手作り演出を入れるべきシーン一覧を作ってください。
```

候補例:

- 冒頭の短い導入シーン
- ホワイトボード風のまとめ
- 付箋やメモカード
- チェックリスト
- 左右比較表
- 章タイトルの手書き風演出
- 環境音
- 小さな案内キャラクター
- 重要な一文の大きな表示

## 8. 動画生成AI

動画生成AIは、全シーンに使う必要はありません。

向いている場面:

- 湯気が上がる
- 手が震える
- 水が流れ続ける
- 粒が積もる
- 物が少しずつ変化する
- 昔の記憶がゆっくり動く

向いていない場面:

- 数字
- 表
- チェックリスト
- 出典
- 日本語文字を正確に出す場面

動画生成AIを使うかどうかは人によって違うので、Codexにはこう頼むと安全です。

```text
動画化した方が良い場面を優先順位つきで出してください。
動画生成AIを使う場合と、使わない場合の両方で提案してください。
```

## 9. 完成版を書き出す

最後にRemotionでMP4を書き出します。

長い動画では一度で失敗することがあるため、必要に応じて分割レンダーしてから結合します。

Codexにはこう言えます。

```text
完成版MP4を書き出してください。
保存場所は分かりやすい場所にしてください。
```

## 10. YouTube説明欄の最終版

動画が完成したら、補助資料の説明欄下書きや仮チャプターをそのまま使うのではなく、完成動画の内容に合わせて最終調整します。

Codexにはこう言えます。

```text
動画が完成しました。
完成動画の内容に合わせて、YouTube説明欄の最終版を作ってください。

以前渡した補助資料の「説明欄下書き」「仮チャプター」「参考文献・出典メモ」「YouTubeタグ候補」は参考にしてください。
ただし、本編で実際に扱った内容だけを書いてください。
説明欄に貼る本文と、YouTube Studioのタグ候補は分けて出してください。
```

正確なタイムスタンプがまだ分からない場合は、先にこう言います。

```text
完成動画の正確なタイムスタンプがまだ不明な場合は、
まず動画内の章構成に基づいたタイムスタンプ確認リストを作ってください。
私が実際の時間を確認して入力した後、YouTube説明欄の最終版を作成してください。
```

出力は次の2つに分けます。

- `YouTube動画説明欄・コピペ用`: YouTubeの説明欄に貼る本文
- `YouTubeタグ候補`: YouTube Studioのタグ欄に入れる候補

## 注意点

- `.env` に入れたAPIキーはGitHubに上げないでください。
- 画像や音声を上書きする前に、必要ならバックアップしてください。
- シーンIDは途中でむやみに変えない方が安全です。
- 数値や表は動画生成AIではなく、Remotion側で作る方が安全です。
- まず確認、次に実装、という順番を守ると失敗が減ります。
