# Remotion物語動画ワークフロー

このドキュメントは、新しい台本からRemotionの長尺動画を作るときに、初心者でも迷いにくいようにするための進行手順です。

ポイントは、いきなりRemotionやmanifestを作らないことです。先に厳密テロップ分割、シーン計画＋画像グループ候補、画像プロンプトを人間が確認できるようにしておくと、あとから直す作業がかなり楽になります。

## 最初にCodexへ言うこと

```text
新しい台本を渡します。
まず厳密テロップ分割から確認しながら進めてください。
通常はシーン1から、【A. 完成台本】の全文を対象にしてください。
長い場合は、確認しやすい範囲に分けて進めてください。
```

Codexは、初心者にはまず次の貼り方を案内します。

```text
下の形で貼ってください。
補助資料がない場合は、【B. 補助資料】は空欄で大丈夫です。

【A. 完成台本】
ここに動画本編で読み上げる台本を貼る

【B. 補助資料】
ここに説明欄下書き、仮チャプター、出典、タグ候補などを貼る
```

補助資料も一緒に渡す場合は、次のように言うと安全です。

```text
完成台本と補助資料を渡します。
動画本編に使ってよいのは【A. 完成台本】だけです。
【B. 補助資料】は、説明欄作成、チャプター調整、参考文献整理、タグ候補作成のためだけに使ってください。
台本と補助資料の境界が不明な場合は、作業前に質問してください。
```

## 全体の流れ

1. 台本と、必要なら補助資料を渡す
2. 本編に使う範囲と、補助資料として扱う範囲を確認する
3. 厳密テロップ分割を作る
4. 人間がテロップ分割を確認・修正する
5. 画風を確認する
6. シーン計画＋画像グループ候補を作る
7. 人間がまとめて確認・修正する
8. 必要な人物のキャラクターマスター画像用プロンプトを作る
9. 外部の画像生成AIでキャラクターマスター画像を作る
10. マスター画像を参照しながら、画像プロンプトを作る
11. 外部の画像生成AIで画像を作る
12. 画像と音声をプロジェクトへ入れる
13. manifestを作る
14. Remotionで確認する
15. 読み間違い修正・画像差し替えを行う
16. 手作り演出の候補を出す
17. 必要な場面だけ動画生成AI用プロンプトを作る
18. 完成版MP4を書き出す
19. 補助資料と実際の動画内容をもとに、YouTube説明欄の最終版を作る

## 0. 台本と補助資料の切り分け

補助資料は、動画本編の素材ではありません。

最初にユーザーが迷わないように、Codexは「完成台本」と「補助資料」を分けて貼るための短いテンプレートを出します。
補助資料がない場合は、空欄のままで進めて大丈夫です。

貼ってもらった内容は、チャット欄だけに残すのではなく、物語フォルダの `metadata` に保存します。

```text
public/assets/your-story/metadata/source-script.md
public/assets/your-story/metadata/supplemental-notes.md
```

`source-script.md` は、厳密テロップ分割の基準になる原文です。
`supplemental-notes.md` は、説明欄、チャプター、出典、タグ候補などに使う補助資料です。
この2つを分けて保存しておくと、後からチャットの記憶が薄れても、原文を確認し直せます。

物語フォルダ名がまだ決まっていない場合、Codexがタイトルから短い半角英数字の名前を提案します。

同じように、後工程で使う大事なものは保存してから次へ進みます。

```text
metadata/telop-split.md
metadata/visual-style.md
metadata/scene-plan-image-groups.md
metadata/characters.md
prompts/character-master-prompts.md
inbox/characters/
images/characters/CHAR001_MASTER.png
inbox/images/
prompts/image-groups-001-010.md
metadata/asset-map.md
metadata/production-log.md
metadata/timestamp-checklist.md
metadata/youtube-publishing-final.md
```

チャット欄は相談の場として使い、保存ファイルを後工程の基準にします。

使ってよい用途:

- 動画の中心論点を理解する
- 説明欄の最終版を作る
- チャプターを実際の動画時間に合わせる
- 参考文献や出典を整理する
- YouTubeタグ候補を出す
- 作業中の変更点を記録する

使ってはいけない用途:

- ナレーション本文に混ぜる
- テロップ本文にする
- 勝手に新しい本編シーンとして追加する
- 未確認のURLや出典を作る

台本と補助資料の区切りが曖昧な場合、Codexは先に質問します。

## 1. 厳密テロップ分割

台本を受け取ったら、Codexはまず厳密テロップ分割案を作ります。

この段階では、画風、画像グループ、キャラクター、演出案は付けません。原文を一字一句そのまま使い、テロップとして読みやすい単位に分けるだけです。

通常は、開始番号はシーン1で大丈夫です。
また、基本は【A. 完成台本】の全文を対象にします。
ただし、全文が長くて確認しにくい場合は、Codexが区切りのよい範囲に分けて出します。

確認すること:

- シーン1から始まっているか
- 原文にない言葉が入っていないか
- 原文の言葉が消えていないか
- 1行20文字以内になっているか
- 1シーン最大2行になっているか
- 20文字以内の文を不要に2行へ分けていないか
- 2行に収まる1文を不要に複数シーンへ分けていないか
- 長文を複数シーンに分ける場合、意味の切れ目で分けているか
- 全シーンをつなげたときに原文と一致するか

分割するときは、必ず次の順番で判断します。

1. まず1文全体を見る
2. 20文字以内であれば、句読点や接続詞があっても1行にまとめる
3. 20文字を超えても、2行以内に自然に収まるなら1シーンにまとめる
4. 2行でも長すぎる文だけ、意味の切れ目で複数シーンに分ける

避けること:

- 句読点があるだけで改行する
- 「なんとなく長そう」という理由で分ける
- 見た目を整えるためだけに短い文を2行にする
- 2行で収まる文を別シーンに分断する

例:

```text
【シーン90】
誰かの手を借りなければ、動けない。
```

この文は1行で収まるため、途中で改行しません。

```text
【シーン96】
でもあの頃の母には、
受け取る余裕がなかったのかもしれません。
```

この文は2行で収まるため、別シーンに分けません。

Codexは、初心者には次のように確認します。

```text
通常はシーン1から始めます。
1番からで進めて大丈夫ですか？

基本は【A. 完成台本】の全文を分割します。
全文で進めて大丈夫ですか？
長い場合は、こちらで確認しやすい範囲に分けて出します。
```

Codexは出力後に、次のように確認します。

```text
この厳密テロップ分割で進めて大丈夫ですか？
原文と違う箇所、区切りを直したい箇所があれば教えてください。
```

承認したテロップ分割は、次のファイルに保存します。

```text
public/assets/your-story/metadata/telop-split.md
```

このファイルはMarkdownなので、手作業で修正できます。
修正した後は、Codexにこう伝えます。

```text
telop-split.md を手作業で修正しました。
source-script.md と照合して、原文が変わっていないか確認してください。
問題なければ次の工程へ進んでください。
```

Codexは `source-script.md` と `telop-split.md` を読み直し、原文の追加・削除・言い換え・順番の入れ替えがないか確認してから次へ進みます。

## 2. 画風の確認

厳密テロップ分割が承認されたら、シーン計画＋画像グループ候補を作る前に画風を確認します。

画風は、テロップ分割には必要ありません。
ただし、シーン計画、画像グループ、キャラクターマスター画像、画像プロンプトには関係します。

Codexにはこう聞かせます。

```text
次にシーン計画＋画像グループ候補を作るため、画風を確認します。
例として、温かみのある手描き風アニメ背景、水彩絵本風、落ち着いたリアル寄り、シンプルなフラットイラスト、漫画風モノクロ、雑誌の挿絵風などがあります。
こんな感じで、という参考画像を渡しても大丈夫です。
```

参考画像を渡す場合は、完全に同じ絵を作るためではなく、雰囲気・色・光・質感・構図の参考として使います。

## 3. シーン計画＋画像グループ候補

厳密テロップ分割が承認されたら、次にシーン計画と画像グループ候補をまとめて作ります。

この工程では、動画としての場面の役割を決めながら、同じ画像で使い回せる範囲も同時に整理します。

確認すること:

- 区切りが細かすぎないか
- 1シーンが長すぎないか
- 感情の変化や説明の区切りが自然か
- 後で画像を作りやすい単位になっているか
- 同じ画像で違和感がないか
- ここだけは別画像にした方がよい場面はないか
- 画像枚数が多すぎないか
- 逆に、使い回しすぎて単調にならないか
- Remotionで作るべき図解や文字演出を、画像生成AIに任せすぎていないか

まずは確認しやすい表で出します。必要なら、構図メモ・制作方法・追加演出候補まで入れた詳細版を出します。

この段階では、まだmanifestを作らないのが大切です。

## 4. キャラクターマスター画像

シーン計画＋画像グループ候補が決まったら、必要に応じてキャラクターマスター画像用プロンプトを作ります。

これは本番の場面画像ではなく、同じ人物を後続の画像で再現するための参照用画像です。
台本を読んですぐ作るより、画像グループが決まった後の方が、誰が何度出るか、現在版と回想版が必要か、一度だけの人物かを判断しやすくなります。

この工程で確認すること:

- 主要人物か、脇役か、一度だけ出る人物か
- どの画像グループに登場するか
- 現在版、若い頃、仕事着などの差分が必要か
- 画像生成せず、既存キャラクター素材としてRemotionで重ねるべきか
- そもそも画像化しない人物ではないか

すでに画風を選んでいる場合は、その画風を自動で反映します。
まだ画風が決まっていない場合は、先に画風を確認します。

画像生成AI用プロンプトの候補は、まず次から選べるようにします。

- `ChatGPT image2.0`
- `Nano Banana Pro`
- `その他`

`その他` を選ぶ場合は、使いたい画像生成AI名をCodexが確認します。
よく分からない場合は、汎用のコピー用プロンプトとして作ります。

Codexにはこう頼むと分かりやすいです。

```text
承認済みのシーン計画＋画像グループ候補をもとに、
登場人物を整理して、必要なキャラクターマスター画像用プロンプトを作ってください。
すでに選んだ画風を自動で反映してください。
画像生成AI用プロンプトは、ChatGPT image2.0 用、Nano Banana Pro 用、その他から選べるようにしてください。
```

基本ルール:

- 文字は入れない
- 背景は白
- 全身正面
- 指定した画風に統一する
- 年齢感、髪型、服装、体型、基本表情、雰囲気を書く
- 同じ人物として後から参照しやすい、シンプルな立ち姿にする
- 既存キャラクター素材は画像生成AIで再生成しない

ユーザーが外部画像生成AIでマスター画像を作ったら、その画像を参照しながら次の画像グループ別プロンプトへ進みます。

作ったキャラクターマスター画像は、Codexが開いた受け取り用フォルダに入れます。
ユーザーは、開いたフォルダへ画像をドラッグ＆ドロップするだけです。

```text
public/assets/your-story/inbox/characters/
```

ファイル名はそのままで大丈夫です。
入れ終わったら、Codexにこう伝えます。

```text
入れました
```

Codexが確認して、必要に応じて次のような名前へ整理します。

```text
CHAR001_MASTER.png
CHAR002_MASTER.png
```

画像グループ用の画像は数が多くなるため、キャラクターマスター画像とは違い、範囲別フォルダと画像IDで受け取ります。
たとえば001〜010の画像は、Codexが `public/assets/your-story/inbox/images/001-010/` を開きます。
外部画像生成AIで作った画像は、できるだけ `img_001.png` のようにプロンプトに書かれている保存名へ変えてから入れます。
完全に同じ名前でなくても、`img_001(2).png` や `img_001_修正版.png` のように画像IDが分かれば、Codexが最終的なファイル名へ整えます。

## 5. 画像プロンプト

画像グループが決まったら、外部の画像生成AIに貼り付けるためのプロンプトを作ります。

この工程では、画像を1シーンごとではなく、同じ画像で使えるまとまりごとに作ります。このまとまりを「画像グループ」と呼びます。

キャラクターマスター画像がある場合は、各画像グループのプロンプトでそのマスター画像を参照します。
顔立ち、髪型、服装、体型、年齢感はマスター画像に合わせます。

長い台本では、画像プロンプトを一気に全部作らず、10〜20画像グループずつ作るのがおすすめです。
たとえば、まず `001〜010` を作り、人間が確認してから `011〜020` に進みます。
この進め方にすると、途中で指示が薄れたり、画像内に文字が入ったり、同じ人物の見た目がぶれたりするミスを見つけやすくなります。
画像生成は、各バッチを確認した後にすぐ行っても、全プロンプトが揃ってからまとめて行っても大丈夫です。

初心者が確認すること:

- この画像で、その場面の雰囲気が伝わるか
- 同じ画像を使う範囲が長すぎないか
- 文字、矢印、チェックリスト、表などが画像に直接入っていないか

読ませたい文字や図解は、あとでRemotion側で重ねます。画像生成AIには、背景、人物、雰囲気、状況が分かる画像だけを作らせます。

通常は、Codexにはこう頼むと分かりやすいです。

```text
まず画像グループ001〜010の画像プロンプトを、コピーできる形で出してください。
画像内に文字は入れないでください。
出力後、ルール違反がないか自己チェックして、次の範囲へ進む前に止まってください。
```

Codexは各バッチの後に、こう案内します。

```text
まず画像グループ001〜010の画像プロンプトを出しました。
確認してください。

次の範囲へ進む場合は「011〜020へ進んで」と言ってください。
```

画像は、ユーザーが使いたい画像生成AIで作ります。
画像を作った後は、Codexが受け取り用フォルダを開きます。
作った画像をドラッグ＆ドロップしてください。

```text
public/assets/your-story/inbox/images/001-010/
```

このフォルダには、画像グループ001〜010の画像だけを入れます。
ダウンロード名が数字の羅列になる場合は、できるだけプロンプトに書かれている保存名へ変えてください。

```text
img_001.png
img_002.png
```

完全に同じ名前でなくても、画像IDが分かれば大丈夫です。

```text
img_001(2).png
img_001_修正版.png
img_002_candidate.png
```

A/B案を両方残す場合は、次のようにします。

```text
img_001_A.png
img_001_B.png
```

Codexが確認後、最終的なファイル名へ整えます。
画像IDが分からない名前のままになっている場合だけ、どのファイルがどの画像IDか分かる簡単なメモを一緒に渡してください。
入れ終わったら、Codexにこう伝えます。

```text
001〜010を入れました
```

この工程では、Codex内で画像生成はしません。Codexは、外部画像生成AIに貼るためのコピー用プロンプトを作ります。

キャラクターの見た目を固定したい、参照画像を使いたい、A/B案を作りたい、Remotionで重ねる要素を細かく分けたい場合は、こう頼みます。

```text
画像プロンプトは詳細版で作ってください。
マスターイメージ固定、既存キャラクターのRemotion配置、画像内テキスト禁止、A/B案、Remotionで重ねる要素の分離まで含めてください。
まず総シーン数と総画像グループ数を確認し、10〜20画像グループずつ、どの範囲から出力するか質問してください。
```

基本ルール:

- 画像グループ単位で作る
- 画像IDは `img_001` の形式にする
- A/B案がある場合は `img_001_A`、`img_001_B` の形式にする
- 各画像グループには、外部画像生成AIから保存するときの保存名も書く
- 画像内に読める文字は入れない
- 既存キャラクターは画像生成AIで再生成しない
- 既存キャラクターはRemotionで重ねる前提で、配置指示だけを書く
- Remotionで重ねる字幕、図解、文字、キャラ配置は、画像プロンプトとは別に書く
- コードブロック内には、外部画像生成AIに貼るプロンプトだけを書く
- 通常は各画像グループ1案だけでよい
- 重要場面だけ、必要に応じてB案も出す
- 長い動画では10〜20画像グループずつ出し、各バッチごとに自己チェックと人間確認を入れる
- 詳細版では、マスターイメージ固定、参照画像の扱い、既存キャラクター配置、A/B案、範囲指定出力まで管理する

Remotionで図解、カード、比較表、チェックリスト、テキスト強調を表示する場面でも、背景画像プロンプトは省略しません。

その場合は、文字や図解を重ねやすい余白を確保した背景画像を作ります。白紙のような寂しい画面にせず、机、ノート、窓辺、柔らかい光、ぼかした部屋、小物など、テーマに合う空気感を入れます。ただし、画像内に読める文字は入れません。

## 6. manifest

manifestは、動画の設計図です。

manifestに入るもの:

- シーンID
- 本文
- 字幕
- 画像ファイル
- 音声ファイル
- 表示時間
- 必要に応じて動画ファイル

厳密テロップ分割、シーン計画＋画像グループ候補を確認してからmanifestを作ると、後の修正が楽になります。

## 7. Remotion確認と修正サイト

Remotionで動画を確認したあと、読み間違いや画像差し替えをしたい場合は、修正サイトを使います。

このテンプレートでは、以下で起動します。

```bash
npm run tools
```

ブラウザで開くURL:

```text
http://localhost:3101/
```

ここでできること:

- 読み間違い修正
- 1シーンだけ音声を作り直す
- 画像差し替え
- 動画ファイルへの差し替え

## 8. 手作り演出

Remotionで基本形ができたら、量産型に見えにくくするために、手作り演出の候補を出します。

Codexにはこう言えます。

```text
新しい物語のmanifestから、手作り演出を入れるべきシーン一覧を作ってください。
```

候補例:

- 冒頭の短い導入シーン
- ホワイトボード風のまとめ
- 付箋やメモカード
- チェックリスト
- 左右比較表
- 章タイトルの手書き風演出
- 環境音
- 小さな案内キャラクター
- 重要な一文の大きな表示

## 9. 動画生成AI

動画生成AIは、全シーンに使う必要はありません。

向いている場面:

- 湯気が上がる
- 手が震える
- 水が流れ続ける
- 粒が積もる
- 物が少しずつ変化する
- 昔の記憶がゆっくり動く

向いていない場面:

- 数字
- 表
- チェックリスト
- 出典
- 日本語文字を正確に出す場面

動画生成AIを使うかどうかは人によって違うので、Codexにはこう頼むと安全です。

```text
動画化した方が良い場面を優先順位つきで出してください。
動画生成AIを使う場合と、使わない場合の両方で提案してください。
```

## 10. 完成版を書き出す

最後にRemotionでMP4を書き出します。

長い動画では一度で失敗することがあるため、必要に応じて分割レンダーしてから結合します。

書き出し前後に、台本から削った内容、追加した図表・テロップ・演出、動画生成AIで足した素材、実際のチャプター候補を短く記録しておきます。
この記録は、最後のYouTube説明欄を「完成動画に実際に入っている内容」へ合わせるために使います。

Codexにはこう言えます。

```text
完成版MP4を書き出してください。
保存場所は分かりやすい場所にしてください。
```

## 11. YouTube説明欄の最終版

動画が完成したら、補助資料の説明欄下書きや仮チャプターをそのまま使うのではなく、完成動画の内容に合わせて最終調整します。

補助資料だけでなく、制作中に記録した変更点も一緒に見ます。
削除した台本内容は説明欄に戻さず、追加した図表・比較・演出・動画素材は必要に応じて反映します。

Codexにはこう言えます。

```text
動画が完成しました。
完成動画の内容に合わせて、YouTube説明欄の最終版を作ってください。

以前渡した補助資料の「説明欄下書き」「仮チャプター」「参考文献・出典メモ」「YouTubeタグ候補」は参考にしてください。
ただし、本編で実際に扱った内容だけを書いてください。
説明欄に貼る本文と、YouTube Studioのタグ候補は分けて出してください。
```

正確なタイムスタンプがまだ分からない場合は、先にこう言います。

```text
完成動画の正確なタイムスタンプがまだ不明な場合は、
まず動画内の章構成に基づいたタイムスタンプ確認リストを作ってください。
私が実際の時間を確認して入力した後、YouTube説明欄の最終版を作成してください。
```

出力は次の2つに分けます。

- `YouTube動画説明欄・コピペ用`: YouTubeの説明欄に貼る本文
- `YouTubeタグ候補`: YouTube Studioのタグ欄に入れる候補

## 注意点

- `.env` に入れたAPIキーはGitHubに上げないでください。
- 画像や音声を上書きする前に、必要ならバックアップしてください。
- シーンIDは途中でむやみに変えない方が安全です。
- 数値や表は動画生成AIではなく、Remotion側で作る方が安全です。
- まず確認、次に実装、という順番を守ると失敗が減ります。
