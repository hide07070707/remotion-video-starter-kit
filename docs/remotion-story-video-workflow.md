# Remotion物語動画ワークフロー

このドキュメントは、新しい台本からRemotionの長尺動画を作るときに、初心者でも迷いにくいようにするための進行手順です。

ポイントは、いきなりRemotionやmanifestを作らないことです。先にシーン分割、画像グループ、画像プロンプトを人間が確認できるようにしておくと、あとから直す作業がかなり楽になります。

## 最初にCodexへ言うこと

```text
新しい台本を渡します。
まずシーン分割から確認しながら進めてください。
```

## 全体の流れ

1. 台本を渡す
2. シーン分割を作る
3. 人間がシーン分割を確認・修正する
4. 画像グループを作る
5. 人間が画像グループを確認・修正する
6. 画像プロンプトを作る
7. 外部の画像生成AIで画像を作る
8. 画像と音声をプロジェクトへ入れる
9. manifestを作る
10. Remotionで確認する
11. 読み間違い修正・画像差し替えを行う
12. 手作り演出の候補を出す
13. 必要な場面だけ動画生成AI用プロンプトを作る
14. 完成版MP4を書き出す

## 1. シーン分割

台本を受け取ったら、Codexはまずシーン分割案を作ります。

確認すること:

- 区切りが細かすぎないか
- 1シーンが長すぎないか
- 感情の変化や説明の区切りが自然か
- 後で画像を作りやすい単位になっているか

この段階では、まだmanifestを作らないのが大切です。

## 2. 画像グループ

画像グループとは、複数のシーンで同じ画像を使うためのまとまりです。

例:

- 同じ台所で会話が続く場面
- 同じ朝食を見せながら説明する場面
- 同じ病院の診察室で会話する場面

確認すること:

- 同じ画像で違和感がないか
- ここだけは別画像にした方がよい場面はないか
- 画像枚数が多すぎないか
- 逆に、使い回しすぎて単調にならないか

## 3. 画像プロンプト

画像グループが決まったら、外部の画像生成AIに貼り付けるためのプロンプトを作ります。

Codexにはこう頼むと分かりやすいです。

```text
画像プロンプトをコピーできる形で出してください。
画像内に文字は入れないでください。
```

画像は、ユーザーが使いたい画像生成AIで作ります。作った画像をプロジェクト内の画像フォルダへ入れたあと、Codexにファイル名を伝えます。

## 4. manifest

manifestは、動画の設計図です。

このテンプレートでは、台本、シーン、画像、音声、字幕、表示時間などをまとめたJSONファイルがmanifestの役割を持っています。

manifestに入るもの:

- シーンID
- 本文
- 字幕
- 画像ファイル
- 音声ファイル
- 表示時間
- 必要に応じて動画ファイル

シーン分割や画像グループを確認してからmanifestを作ると、後の修正が楽になります。

## 5. Remotion確認と修正サイト

Remotionで動画を確認したあと、読み間違いや画像差し替えをしたい場合は、修正サイトを使います。

このプロジェクトでは、以下で起動します。

```bash
npm run tools
```

ブラウザで開くURL:

```text
http://localhost:3101/
```

ここでできること:

- 読み間違い修正
- 1シーンだけ音声を作り直す
- 画像差し替え
- 動画ファイルへの差し替え

## 6. 手作り演出

Remotionで基本形ができたら、量産型に見えにくくするために、手作り演出の候補を出します。

Codexにはこう言えます。

```text
新しい物語のmanifestから、手作り演出を入れるべきシーン一覧を作ってください。
```

候補例:

- 冒頭の短い導入シーン
- ホワイトボード風のまとめ
- 付箋やメモカード
- チェックリスト
- 左右比較表
- 章タイトルの手書き風演出
- 環境音
- 小さな案内キャラクター
- 重要な一文の大きな表示

## 7. Higgsfieldや動画生成AI

動画生成AIは、全シーンに使う必要はありません。

向いている場面:

- 湯気が上がる
- 手が震える
- 水が流れ続ける
- 塩が積もる
- ホースが水圧で張る
- 風船が膨らむ
- 昔の記憶がゆっくり動く

向いていない場面:

- 数字
- 表
- チェックリスト
- 出典
- 日本語文字を正確に出す場面

動画生成AIを使うかどうかは人によって違うので、Codexにはこう頼むと安全です。

```text
動画化した方が良い場面を優先順位つきで出してください。
Higgsfieldを使う場合と、使わない場合の両方で提案してください。
```

## 8. 完成版を書き出す

最後にRemotionでMP4を書き出します。

長い動画では一度で失敗することがあるため、必要に応じて分割レンダーしてから結合します。

Codexにはこう言えます。

```text
完成版MP4を書き出してください。
保存場所はデスクトップにしてください。
```

## 注意点

- `.env` に入れたAPIキーはGitHubに上げないでください。
- 画像や音声を上書きする前に、必要ならバックアップしてください。
- シーンIDは途中でむやみに変えない方が安全です。
- 数値や表は動画生成AIではなく、Remotion側で作る方が安全です。
- まず確認、次に実装、という順番を守ると失敗が減ります。
